# Three.js reconstruction miner

Generation pipeline in `sn17gen/` is derived from research-somthing-t/lumen-kit (commit 3594fd1a), with prompt rules adapted from golden217/sn17gen and from our earlier releases, a two-order final pick, and error-handling changes. Runner and entry point from our earlier release.

Three chains (plain, proportions-first and plain again; each generates, then refines the latest valid module twice against renders from the judge's four front cameras, repairing rejections) run stage by stage: the model calls of a stage run concurrently and all renders happen in a fixed order between stages. Request ids are fixed per chain step, so replay does not depend on thread timing. The final pick compares the candidates pairwise from each of the judge's four front cameras in both orders, with the judge's own Stage-1 wording, and takes the lowest summed penalty. The picked module then gets one more refinement against the four camera views; the refined module is used only if it renders.
